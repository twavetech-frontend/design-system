# iOS Asset Catalog + DS accessor 출력 설계

- 작성일: 2026-05-11
- 대상 레포: `twavetech-frontend/design-system`
- 상태: 설계 합의 완료, 구현 계획 수립 예정
- 영향 받는 외부 레포: `twavetech-frontend/imin-design-system` (iOS 앱) — `sync-design-tokens.sh` 갱신 필요

## 배경

현재 design-system 의 iOS 출력은 `ColorsLight.swift` / `ColorsDark.swift` / `Spacing.swift` / `Typography.swift` 4개 raw Swift 파일이다. iOS 앱 팀(엄기철)이 이 출력을 받아 자체 `sync-design-tokens.sh` (10단계 + Python 2개) 로 다음을 매번 변환한다:

- `Colors*.swift` → Xcode Asset Catalog (`Assets.xcassets/Colors/<name>.colorset/Contents.json`) + `DSColor+Generated.swift` accessor
- `Spacing.swift` → `DSSpacing+Generated.swift` (semantic only, prefix 제거, `2xl`→`xl2` swap)
- `Typography.swift` → `DSFont+Generated.swift` (DSFontRegistration 호출 포함)

이 변환 로직을 design-system 레포가 직접 수행하도록 흡수하면 iOS 앱의 sync 가 단순 `clone + cp` 로 축소된다.

## 목표

- design-system 의 `ios/` 출력을 Asset Catalog + DS accessor 4종으로 교체
- iOS 앱의 swift→colorset / swift→DS-tokens 변환기 로직을 design-system 의 build.js 에 흡수
- iOS 앱의 sync 스크립트가 변환 단계 없이 단순 복사로 동작 가능

## 비목표 (스코프 밖)

- **Pretendard 폰트 자산 vendoring** — design-system 은 토큰만, 폰트는 iOS 앱 책임 (디자인 결정 Q1)
- **`DSFontRegistration` 구현** — design-system 은 호출 코드만 emit. 실제 폰트 등록 함수는 iOS 앱(또는 다른 future iOS consumer) 의 자기 module 안에 있어야 함
- **Android / Web 출력 변경** — 이번 작업은 iOS 만. Android 는 별도 피드백 받은 후 결정
- **raw Swift 파일 deprecation 기간** — 단일 consumer (이 iOS 팀) 이므로 즉시 교체

## 출력 구조

### 변경 전 (`design-system/ios/`)

```
ios/
├── ColorsLight.swift     (~1148 줄, public enum LightColors { static let colorsBgPrimary = Color(red:..., green:..., blue:...) ... })
├── ColorsDark.swift      (~1148 줄, 동일 패턴 enum DarkColors)
├── Spacing.swift         (primitives + semantics 모두; spacingNone / spacingXxs / spacing00px / spacing052px ...)
└── Typography.swift      (public extension Font { static let display2xlRegular = Font.custom("Pretendard", size: 72).weight(.regular) ... })
```

### 변경 후 (`design-system/ios/`)

```
ios/
├── Assets.xcassets/
│   ├── Contents.json                              (root catalog 메타)
│   └── Colors/
│       ├── Contents.json                          (folder provider)
│       ├── colorsBgPrimary.colorset/
│       │   └── Contents.json                      (light + dark appearances 한 파일)
│       ├── colorsTextPrimary.colorset/
│       │   └── Contents.json
│       └── ... (총 1143개 .colorset 디렉토리, gradient 토큰 111개 제외)
├── DSColor+Generated.swift                        (accessor: Color("name", bundle: .module))
├── DSSpacing+Generated.swift                      (semantic only: none/xxs/xs/sm/md/lg/xl/xl2/xl3/...)
├── DSRadius+Generated.swift                       (동일 패턴)
└── DSFont+Generated.swift                         (Font + DSFontRegistration.register() 호출)
```

기존 4개 raw Swift 파일은 완전 삭제 (git rm 효과는 build 가 새 파일을 emit 하면서 자연 발생).

## 변환 규칙

### A. 색상 → `.colorset` Contents.json

**입력:** SD `getPlatformTokens('css')` 의 light/dark dictionary 에서 `$type === 'color'` 토큰만 (`isPlainColor` 필터 적용; gradient 같은 비-hex/rgba 문자열은 SKIP).

**디렉토리명:** 토큰의 `name` 그대로 (`colorsBgPrimary` 등). 이미 SD 의 `name/camel` transform 결과로 pure camelCase.

**Light/Dark 통합:**
- light 와 dark 의 RGBA 가 다르면 → 두 엔트리 (universal + `appearances:[{appearance:"luminosity",value:"dark"}]`)
- light 와 dark 가 같으면 → universal 하나만 (mode 무관 동일)
- dark 에만 있는 토큰 → universal 로 dark 값 emit + stderr 경고

**components 형식:** `f"{value:.3f}"` 3자리 소수점 문자열. 색상공간 항상 `"srgb"`.

**예시 (colorsBgPrimary.colorset/Contents.json):**

```json
{
  "info": { "author": "xcode", "version": 1 },
  "colors": [
    {
      "idiom": "universal",
      "color": {
        "color-space": "srgb",
        "components": { "red": "0.957", "green": "0.925", "blue": "1.000", "alpha": "1.000" }
      }
    },
    {
      "idiom": "universal",
      "appearances": [{ "appearance": "luminosity", "value": "dark" }],
      "color": {
        "color-space": "srgb",
        "components": { "red": "0.204", "green": "0.000", "blue": "0.471", "alpha": "1.000" }
      }
    }
  ]
}
```

**root catalog 메타 (`Assets.xcassets/Contents.json`):**

```json
{ "info": { "author": "xcode", "version": 1 } }
```

**folder provider (`Assets.xcassets/Colors/Contents.json`):**

```json
{
  "info": { "author": "xcode", "version": 1 },
  "properties": { "provides-namespace": true }
}
```

`provides-namespace: true` 로 인해 Xcode 에서 `Color("colorsBgPrimary")` 가 아닌 `Color("Colors/colorsBgPrimary")` 가 될지 여부 확인 필요. 일반적으로는 namespace 제공 시 path-prefixed 가 됨. iOS 팀의 기존 변환기는 namespace 명시 안 함 — 일관성을 위해 이 spec 도 **namespace 제공 안 함** (`Contents.json` 내용은 `{"info":{"author":"xcode","version":1}}` 만, namespace 키 생략) — accessor 가 `Color("colorsBgPrimary")` 그대로 동작.

### B. DSColor accessor

**파일:** `DSColor+Generated.swift`

```swift
// Auto-generated by build.js — do not edit.
import SwiftUI

public enum DSColor {
    public static let colorsBaseBlack = Color("colorsBaseBlack", bundle: .module)
    public static let colorsBaseWhite = Color("colorsBaseWhite", bundle: .module)
    public static let colorsBgPrimary = Color("colorsBgPrimary", bundle: .module)
    ...
}
```

- 이름 알파벳순 정렬
- 1143개 (colorset 과 동일 개수, gradient 제외)
- `bundle: .module` — Swift Package 자기 module 안 assets 임을 명시

### C. DSSpacing / DSRadius

**필터:** 이름에 "px" 포함되면 primitive scale 로 간주 SKIP (`spacing00px`, `spacing14px` 등). semantic 만 남김.

**Rename:**
- prefix 제거 + first char lowercase: `spacingMd` → `md`, `radiusFull` → `full`
- 숫자 시작 식별자 swap: `2xl` → `xl2`, `3xl` → `xl3`, ..., `10xl` → `xl10`
- 정수 표현 가능하면 정수, 아니면 소수 그대로

**Dedup:** 동일 normalized name 중복 시 나중 값으로 덮어씀, 순서는 첫 등장 유지.

**파일:** `DSSpacing+Generated.swift`

```swift
// Auto-generated by build.js — do not edit.
import CoreGraphics

public enum DSSpacing {
    public static let none: CGFloat = 0
    public static let xxs: CGFloat = 2
    public static let xs: CGFloat = 4
    public static let sm: CGFloat = 6
    public static let md: CGFloat = 8
    public static let lg: CGFloat = 12
    public static let xl: CGFloat = 16
    public static let xl2: CGFloat = 20
    public static let xl3: CGFloat = 24
    public static let xl4: CGFloat = 32
    ... (등등, 동일 패턴)
}
```

**파일:** `DSRadius+Generated.swift` — 동일 패턴, enum 이름만 `DSRadius`.

### D. DSFont

**파일:** `DSFont+Generated.swift`

```swift
// Auto-generated by build.js — do not edit.
import SwiftUI

public enum DSFont {
    // Pretendard 폰트 자동 등록 — 어떤 멤버에 처음 접근해도 1회 실행됨
    private static let _registered: Void = DSFontRegistration.register()

    public static let display2xlRegular: Font = { _ = _registered; return Font.custom("Pretendard", size: 72).weight(.regular) }()
    public static let textBodyM: Font = { _ = _registered; return Font.custom("Pretendard", size: 16).weight(.regular) }()
    ...
}
```

- 토큰 이름 그대로 (Spacing/Radius 와 달리 rename 없음 — `textBodyM`, `display2xlRegular`)
- `_registered` lazy var 가 폰트 등록을 정확히 1회 트리거
- **`DSFontRegistration.register()` 는 iOS 앱(또는 future consumer) 측 구현** — design-system 은 컴파일러 dependency 만 생성

## build.js 변경

### 제거

- `sdLight.platforms.ios` 전체 (현재 ColorsLight.swift, Spacing.swift, Typography.swift 출력)
- `sdDark.platforms.ios` 전체 (현재 ColorsDark.swift 출력)
- `iosColorsFormatDef`, `iosSpacingFormatDef`, `iosTypographyFormatDef` register 호출
- 위 4개 import

### 추가

기존 `await sdLight.buildAllPlatforms()` + `await sdDark.buildAllPlatforms()` + `generateTokensTs` 흐름 이후, post-build 블록:

```js
import { generateAssetCatalog } from './formats/ios-asset-catalog.js';
import { generateDSColorAccessor } from './formats/ios-ds-color-accessor.js';
import { generateDSSpacing } from './formats/ios-ds-spacing.js';
import { generateDSFont } from './formats/ios-ds-font.js';

// ... (기존 generateTokensTs 코드)

const lightDict = await sdLight.getPlatformTokens('css');
const darkDict = await sdDark.getPlatformTokens('css');

// 1. Asset Catalog (root + folder provider + 1143개 colorset)
const catalogFiles = generateAssetCatalog({
  lightColors: lightDict.allTokens,
  darkColors: darkDict.allTokens,
});
for (const [filepath, content] of catalogFiles) {
  fs.mkdirSync(path.dirname(filepath), { recursive: true });
  fs.writeFileSync(filepath, content);
}

// 2. DSColor accessor
fs.writeFileSync('ios/DSColor+Generated.swift', generateDSColorAccessor(lightDict.allTokens));

// 3. DSSpacing + DSRadius
const { spacingContent, radiusContent } = generateDSSpacing(lightDict.allTokens);
fs.writeFileSync('ios/DSSpacing+Generated.swift', spacingContent);
fs.writeFileSync('ios/DSRadius+Generated.swift', radiusContent);

// 4. DSFont
fs.writeFileSync('ios/DSFont+Generated.swift', generateDSFont(lightDict.allTokens));
```

## iOS 앱 측 영향

design-system 변경이 푸시되면 iOS 앱의 기존 `sync-design-tokens.sh` 는 `cp $SRC/ColorsLight.swift` 단계에서 **즉시 실패**한다 (파일 없음). 완화책:

### 권장 완화

1. **README 에 새 sync 스크립트 샘플 포함** — iOS 팀이 자기 스크립트 업데이트 시 참고. 새 스크립트는 ~3 단계:

   ```bash
   # 1) Clone design-system sparse ios/
   git clone --depth=1 --filter=blob:none --sparse --branch main \
       https://github.com/twavetech-frontend/design-system.git "$CACHE_DIR"
   git -C "$CACHE_DIR" sparse-checkout set ios

   # 2) Copy Asset Catalog + DS accessor
   rm -rf "$DEST_DIR"
   mkdir -p "$DEST_DIR" "$ASSETS_DIR"
   cp "$CACHE_DIR/ios"/DS*+Generated.swift "$DEST_DIR/"
   cp -r "$CACHE_DIR/ios/Assets.xcassets/." "$ASSETS_DIR/"

   # 3) Pretendard 폰트 (이전 그대로)
   # ... curl orioncactus/pretendard ...

   # 4) swift build
   ```

2. **머지 시점 사전 조율** — design-system PR 머지 전 iOS 팀에 알림 → 양쪽 동시 업데이트.

3. **iOS 앱이 `DSFontRegistration` 함수를 제공하는지 확인** — 기존 swift_to_ds_tokens.py 가 동일 코드를 emit 했으니 이미 있을 것으로 추정. 미확인 시 사전 확인.

## 테스트 전략

각 generator 는 pure function (input → output string 또는 Map). 표준 패턴:

- 픽스처 light/dark dictionary 만들고 generator 호출
- 출력 string 또는 Map 검증
- Asset Catalog 의 경우 JSON 라운드트립으로 components / appearances 확인

기존 daemon translator snapshot test (Phase 2 에서 갱신했던 것) 는 manifest 데이터만 사용 — 우리 iOS 파일 자체를 보지 않음. 영향 없을 것으로 추정하지만 sanity check 필요.

## 리스크

- **Asset Catalog 의 1143 개 .colorset 디렉토리** — git diff 가 매우 시끄러워질 수 있음. PR 리뷰 시 `ios/Assets.xcassets/` 디렉토리 통째 변경. 첫 머지 이후로는 차이 없을 가능성 높음 (token 변경 시 변경되는 colorset 만 git stat 으로 보임)
- **CI 빌드 시간** — generator 가 1143 파일을 emit. fs.writeFileSync 순차 호출이라 가벼움 (체감 안 될 것). 측정 필요
- **iOS 앱 sync 스크립트 깨짐** — 위 완화책으로 대응
